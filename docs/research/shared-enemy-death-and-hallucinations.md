# Shared Enemy death and hallucination follow-up

Light source review for [#51](https://github.com/amnesia-spelos/amnesia-multiplayer/issues/51), following the successful manual Multiplayer Session reported on 2026-10-17. The reported Brute and custom-enemy behavior is useful exploratory evidence, not a claim of complete support.

Primary sources: game checkout at `5701e67533a5fcec329491504cc5dbfea07efb73`; Game Peer checkout at `bc18088bfdb05affacf48080ad961900881dc239`. This review reads code; it does not independently reproduce LAN behavior or inspect every Custom Story's scripts.

## Death policy: supported direction, with a crucial predicate

**Use an installed death callback as the branch condition, rather than the existence of a checkpoint.** Every newly entered map receives an automatic checkpoint named `_auto`, with an empty callback, before `OnEnter`. Therefore almost every ordinary map already has a checkpoint even when its Map Script has registered no death listener. Script `CheckPoint(...)` replaces the current registration through `SetCheckPoint`. [Automatic checkpoint](https://github.com/amnesia-spelos/amnesia-tdd-tcp/blob/5701e67533a5fcec329491504cc5dbfea07efb73/src/amnesia/src/game/LuxMapHandler.cpp#L441-L479), [script binding](https://github.com/amnesia-spelos/amnesia-tdd-tcp/blob/5701e67533a5fcec329491504cc5dbfea07efb73/src/amnesia/src/game/LuxScriptHandler.cpp#L1035-L1042).

The engine stores one current checkpoint name, start position, callback and death count per map. Re-registering the **same name returns without changing anything**, including the callback; a new name resets the count to zero. Saved-map state restores all four fields. Detect the actual current callback, not whether `CheckPoint` was ever called, an assumed name, or a static scan of the `.hps` file. A nonempty callback is evidence that the story supplied death handling; it does not prove that death is mandatory or that the callback changes maps. [Registration](https://github.com/amnesia-spelos/amnesia-tdd-tcp/blob/5701e67533a5fcec329491504cc5dbfea07efb73/src/amnesia/src/game/LuxMap.cpp#L471-L478), [restore](https://github.com/amnesia-spelos/amnesia-tdd-tcp/blob/5701e67533a5fcec329491504cc5dbfea07efb73/src/amnesia/src/game/LuxSavedMap.cpp#L236-L243).

Ordinary death restores health and then calls `LoadCheckPoint`; that function repositions the local player, deactivates and resets every non-driven enemy, resets music, invokes the current death callback with `(checkpointName, count)`, and increments the count **after** the callback. Driven copies already skip the enemy reset. There is no conditional branch that avoids those resets when the callback is empty. Thus preserving Shared Enemies without a death callback requires a new targeted exception in the Session Host's reset path; merely skipping callback replay does not preserve them. [Player reset](https://github.com/amnesia-spelos/amnesia-tdd-tcp/blob/5701e67533a5fcec329491504cc5dbfea07efb73/src/amnesia/src/game/LuxPlayerHelpers.cpp#L2302-L2327), [checkpoint reset and callback](https://github.com/amnesia-spelos/amnesia-tdd-tcp/blob/5701e67533a5fcec329491504cc5dbfea07efb73/src/amnesia/src/game/LuxMap.cpp#L511-L550).

There is also an earlier enemy `PlayerDead` message at the beginning of the death sequence. Grunt handling switches to Idle; the common handler already suppresses that message while pursuing a live Avatar. Preserving active state alone does not promise uninterrupted pursuit or target retention. Existing range checks consider the nearest eligible player and can still legitimately deactivate an out-of-range enemy. Scope the exception to death-caused reset, without disabling ordinary range or script behavior. [Death broadcast](https://github.com/amnesia-spelos/amnesia-tdd-tcp/blob/5701e67533a5fcec329491504cc5dbfea07efb73/src/amnesia/src/game/LuxPlayerHelpers.cpp#L2004-L2006), [message guard](https://github.com/amnesia-spelos/amnesia-tdd-tcp/blob/5701e67533a5fcec329491504cc5dbfea07efb73/src/amnesia/src/game/LuxEnemy.cpp#L869-L874), [Grunt handlers](https://github.com/amnesia-spelos/amnesia-tdd-tcp/blob/5701e67533a5fcec329491504cc5dbfea07efb73/src/amnesia/src/game/LuxEnemy_Grunt.cpp#L163-L168), [range check](https://github.com/amnesia-spelos/amnesia-tdd-tcp/blob/5701e67533a5fcec329491504cc5dbfea07efb73/src/amnesia/src/game/LuxEnemy.cpp#L1659-L1678).

## Killing all players does not itself prove aligned progression

The proposed shared death when a death callback is installed is a reasonable compatibility policy: each game's own death path can run its own registered callback. It replaces the original rule in [ADR 0009](../adr/0009-session-host-simulates-shared-enemies.md), where a single death never reset a Shared Enemy and only both dead permitted vanilla reset. The ADR is amended alongside this review to record the new policy; implementation and LAN verification remain open.

The callback can request `ChangeMap`, which schedules a transition, fades out, and disables the local player; the actual change waits for the fade. The source therefore supports the concern that death handling can move a game to another map. It does **not** prove that killing everyone at different times produces the same progression. Checkpoint registration/counts and ordinary story state must agree, every participating game must enter its death path once, and delayed death messages must not affect the next Map Visit. A callback that replaces its own checkpoint is another ordering case: `LoadCheckPoint` increments the current count after executing it. [Deferred transition](https://github.com/amnesia-spelos/amnesia-tdd-tcp/blob/5701e67533a5fcec329491504cc5dbfea07efb73/src/amnesia/src/game/LuxMapHandler.cpp#L397-L408), [transition gate](https://github.com/amnesia-spelos/amnesia-tdd-tcp/blob/5701e67533a5fcec329491504cc5dbfea07efb73/src/amnesia/src/game/LuxMapHandler.cpp#L601-L614), [callback/count ordering](https://github.com/amnesia-spelos/amnesia-tdd-tcp/blob/5701e67533a5fcec329491504cc5dbfea07efb73/src/amnesia/src/game/LuxMap.cpp#L546-L550).

Recommendation: decide and latch a single shared-death episode at death onset, with a Map Visit identity and a deduplication key. Run each game's own vanilla death/callback once; do not additionally relay the checkpoint callback as a Shared Callback. Verify count equality across repeated deaths, and define handling for mismatched registration or a player already changing maps. These are implementation recommendations, not behavior established by this source review.

Follow-up proposal: carry an agreed checkpoint callback count with the shared-death episode so both games pass the same value to their own registered callback. The callback receives the pre-increment count (initially zero), not a player's lifetime deaths; keep the stored next count consistent too. Use a checkpoint registration identifier/generation and current map/visit identity instead of sending a function name, following ADR 0006's registration lookup boundary. The Session Host's Game Peer can order/coalesce simultaneous death reports into one episode; the count-selection and registration-mismatch policy still need definition. Apply the agreed count at each game's normal checkpoint-completion seam, once, preserving its respawn/reset work and avoiding a second callback replay. Test callbacks that replace the checkpoint before the post-callback increment. Ordinary Shared Callback replay is not a drop-in replacement: ADR 0006 keeps checkpoint callbacks local, suppresses player-control calls during replay, and queues ordinary callbacks across maps; death coordination needs explicit timing and stale-visit rules.

Hard Mode/save reload and permanent death have separate paths. Keep them explicitly outside the ordinary checkpoint guarantee until exercised; their existence prevents a universal claim that every death only invokes `LoadCheckPoint`. [Hard Mode and permanent-death paths](https://github.com/amnesia-spelos/amnesia-tdd-tcp/blob/5701e67533a5fcec329491504cc5dbfea07efb73/src/amnesia/src/game/LuxPlayerHelpers.cpp#L2060-L2175).

## Hallucinations: trigger and disappearance are both missing seams

`UpdateHallucination` only tests squared distance to the **local** player's character-body position, with a strict `<` threshold, and only for a living hallucination enemy. It neither checks the current target nor an Avatar. Driven copies return before this update, so a Joining Player approaching its copy cannot independently trigger it. Expand the Session Host's check to the nearest eligible local player or Avatar on the map, independent of which player the enemy targets. The existing Avatar target enumeration provides a plausible seam, but requires enemy sight enabled and an active body; eligibility for hallucinations must be deliberate. [Hallucination check](https://github.com/amnesia-spelos/amnesia-tdd-tcp/blob/5701e67533a5fcec329491504cc5dbfea07efb73/src/amnesia/src/game/LuxEnemy.cpp#L1879-L1887), [driven early return](https://github.com/amnesia-spelos/amnesia-tdd-tcp/blob/5701e67533a5fcec329491504cc5dbfea07efb73/src/amnesia/src/game/LuxEnemy.cpp#L634-L637), [Avatar eligibility](https://github.com/amnesia-spelos/amnesia-tdd-tcp/blob/5701e67533a5fcec329491504cc5dbfea07efb73/src/amnesia/src/game/LuxAvatarHandler.cpp#L90-L113).

The poof is `FadeToSmoke(true)`: particles at skeleton bones, a one-second dissolve when visible, deactivation, and a hallucination disappearance GUI sound. Relay this semantic effect with its sound flag so the receiving game renders its own full effect. Script `FadeEnemyToSmoke` calls the same method, suggesting a common hook that can cover both proximity and scripted disappearance. [Full effect](https://github.com/amnesia-spelos/amnesia-tdd-tcp/blob/5701e67533a5fcec329491504cc5dbfea07efb73/src/amnesia/src/game/LuxEnemy.cpp#L1060-L1094), [scripted fade](https://github.com/amnesia-spelos/amnesia-tdd-tcp/blob/5701e67533a5fcec329491504cc5dbfea07efb73/src/amnesia/src/game/LuxScriptHandler.cpp#L3100-L3109).

Enemy Poses carry motion/animation, not disappearance. The game only samples active Grunt-type enemies and removes missing entries from its outbound set, but the Game Peer relays individual reports; it does not send a complete-set deletion. A Joining Player therefore receives no poof just because the Session Host stops reporting. Releasing a driven copy restores its pre-drive active flag, another resurrection risk after deactivation. An ordered, idempotent poof event needs persistent inactive lifecycle state, stale-pose rejection, and a clear reactivation/reset rule. Do not assume a stream timeout or `enemyrelease` reproduces the effect. [Sampling filter](https://github.com/amnesia-spelos/amnesia-tdd-tcp/blob/5701e67533a5fcec329491504cc5dbfea07efb73/src/amnesia/src/game/LuxSocketServer.cpp#L134-L145), [complete local outbound replacement](https://github.com/amnesia-spelos/amnesia-tdd-tcp/blob/5701e67533a5fcec329491504cc5dbfea07efb73/src/amnesia/src/game/GameInteractionGateway.cpp#L354-L359), [individual Game Peer forwarding and release](https://github.com/amnesia-spelos/amnesia-multiplayer/blob/bc18088bfdb05affacf48080ad961900881dc239/src/Multimnesia.Client/SharedEnemies.cs#L63-L123), [release restores active flag](https://github.com/amnesia-spelos/amnesia-tdd-tcp/blob/5701e67533a5fcec329491504cc5dbfea07efb73/src/amnesia/src/game/LuxEnemy.cpp#L2980-L3019).

## Suggested acceptance cases

- Default `_auto`/empty-callback map: die as Session Host, then as Joining Player; the same Shared Enemy stays active and can hunt the survivor. Repeat with both dying close together. Observe AI continuity separately from mere visibility.
- Scripted death callback without map change: either player initiates one shared-death episode; both execute their own callback once with equal counts. Repeat to cover count increments and checkpoint replacement/re-registration.
- Death callback requesting a map transition: both reach the same destination/start; vary death-screen timing, trigger simultaneous deaths, and deliver a delayed duplicate after transition. No second death or callback occurs in the new Map Visit.
- Deliberately mismatched current checkpoint registrations and a player already on another map: verify the defined policy rather than assuming synchronized scripts.
- Hallucination: Session Host alone approaches, Joining Player alone approaches, then both approach together; one poof per game includes particles, dissolve and sound. The approaching player need not be the AI target. Check threshold and vertical-distance behavior against vanilla.
- After poof: delayed Pose, departure/release, reconnect, same-map revisit, and intended script reactivation do not accidentally resurrect it or replay the effect. Scripted fade with sound disabled remains silent.
- Retain Grunt coverage; record the actual entity type/assets for exploratory Brute and custom-enemy checks before expanding support claims. The current game sampling/drive gate is explicitly Grunt-type.

These cases remain manual or automated acceptance work. Successful exploratory play does not settle callback ordering, repeated deaths, stale messages, or lifecycle transitions.
